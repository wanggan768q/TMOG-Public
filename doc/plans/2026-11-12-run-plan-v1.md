## 4. 每票流程

1. Worker 读 Issue 合同与角色合同 → 回 READY → Lead 发 ACK（赋值已含范围/验收/base/worktree/报告路径）。
2. 本票 worktree 内 `doc/plans/` 写实施计划。
3. 开发 + 自验证（Debug 构建/ctest 全绿；UI 或部署证据；Release 至少构建通过）。
4. Worker 报 head，Lead 派 **fresh** 独立本地审查（≤3 轮，作者不得自审，审查须独立复跑验证命令）。
5. 审查 PASS 且获 Lead 明确授权后，Worker push 分支并建 PR（正文 `Part of #N`，不写 Closes/Fixes）。
6. Lead 派**新的** fresh PR 审查（≤3 轮，覆盖 diff、reviewThreads、closingIssuesReferences、numstat、构建测试原始证据）。
7. 低风险合并门槛全部满足时，由 IssueWriter 用 `gh pr merge --merge --match-head-commit <head>` 合并（每轮最多一票）；不满足则 hold 并问用户。
8. 合并后核对 `state/mergedAt/mergeCommit/headRefOid`，Lead 同步主树并跑全量构建/ctest，按 Issue 验收逐条关票；部分交付不关整票。
